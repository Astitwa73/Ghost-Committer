# 👻 Ghost Committer: Project Report & Technical Roadmap
Date: May 3, 2026

## 1. WHAT HAS BEEN DONE (In Detail)

Over the course of this session, the Ghost Committer agent was transformed from a partially broken prototype into a fully operational, high-integrity AI pipeline.

### A. Infrastructure & Stability (Layer 5: Validator)
- **The Problem:** The Docker sandbox was failing with 'ModuleNotFoundError' because it lacked the system dependencies required by GitPython (git) and llama-cpp-python (C++ compiler).
- **The Fix:** Refactored `validator/sandbox.py`. The sandbox now:
    1. Uses `apt-get` to install `git` and `build-essential`.
    2. Upgrades `pip` to the latest version.
    3. Correctly installs all dependencies from `requirements.txt` within the container.
- **Result:** The pipeline now achieves "Green" status (passing tests) in a fully isolated, production-grade environment.

### B. Intelligent Scanning (Layer 2: Scanner)
- **The Problem:** The scanner was including the `.venv` directory, causing noise, slow performance, and incorrect reports. It also lacked the depth to find complex code or missing documentation.
- **The Fix:** 
    1. **Scope Refinement:** Modified `scanner/engine.py` to strictly exclude `.venv` and `.git` folders.
    2. **Enhanced Metrics:** Added new heuristic methods to detect:
        - **TODO/FIXME Comments:** Locates pending tasks in the code.
        - **Complex Functions:** Identifies functions with high nesting/cyclomatic complexity.
        - **Missing Docstrings:** Flags exported functions that lack documentation.
    3. **Flattened Vulnerabilities:** Fixed the `pip-audit` parser to correctly extract and flatten vulnerability data for the LLM.

### C. Local AI Integration (Layer 3: Planner)
- **The Problem:** The agent was running in "Mock Mode" (simulated plans).
- **The Fix:** 
    1. **Model Deployment:** Successfully downloaded and configured a local **Phi-3 Mini GGUF** model (~2.4GB).
    2. **Prompt Engineering:** Updated `planner/agent.py` to feed the new scanner metrics (TODOs, complexity, etc.) into the AI.
- **Result:** The agent now generates real, logical fix plans based on actual code analysis without sending data to an external API.

### D. Code Quality & Cleanup
- Resolved **8 Linting Issues** across the codebase (unused imports, unused variables, implicit re-exports).
- Implemented a **Tech Debt Scenario** in `test_dummy.py` to prove the agent can detect and plan fixes for real-world issues.

## 2. HOW TO USE THE SYSTEM

### Step 1: Environment Setup
1. Ensure **Docker Desktop** is running.
2. Activate your venv: `.\.venv\Scripts\Activate.ps1`
3. Verify the model exists in `models/phi-3-mini-4k-instruct.Q4_K_M.gguf`.

### Step 2: Running the Pipeline
Execute the orchestrator:
```bash
python main.py .
```

### Step 3: Monitoring Output
1. **Scanner Phase:** Watch the console for the "Scan Report" summary.
2. **Planner Phase:** Review the AI-generated "Proposed Plan."
3. **Patcher Phase:** The agent will create a new branch and apply a (currently mock) fix to `dummy_fix.txt`.
4. **Validator Phase:** The Docker sandbox will spin up. **Note:** The first run is slow as it builds the container environment; subsequent runs are cached.
5. **Delivery Phase:** If tests pass, a PR dry-run summary is printed.

---

## 3. THE 5-LAYER PIPELINE (Technical Deep Dive)

1. **Layer 2 (Scanner):** Orchestrates `ruff` (linting), `vulture` (dead code), `pip-audit` (security), and custom regex-based scanners (TODOs/Complexity). Outputs a JSON Report.
2. **Layer 3 (Planner):** Loads the Phi-3 model into memory. Ingests the JSON Report. Produces a markdown-formatted Fix Strategy.
3. **Layer 4 (Patcher):** Creates a unique Git branch. Traditionally would use the AI plan to edit files. Currently appends status to `dummy_fix.txt` to prove the branch/commit flow.
4. **Layer 5 (Validator):** Mounts your source code into a `python:3.11-slim` container. Runs `pip install` and `unittest`. This is the "Gatekeeper"—it prevents any AI hallucination from ever reaching your main branch.
5. **Layer 6 (Delivery):** Interfaces with GitHub API and Slack/Telegram. Opens the PR and notifies the team.

- **Goal:** Move from mock patching to **Real Code Edits**.
- **How:** 
    1. **AST Parsing:** Use the `tree-sitter` library (already in requirements) to map the LLM's plan to specific line numbers and code blocks.

    3. **Dependency Auto-Patch:** Wire the `pip-audit` findings to automatically run `pip install --upgrade <package>` and commit the updated `requirements.txt`.

### Phase 4: Multi-Language Support
- **Goal:** Support Node.js, Go, and Java.
- **How:** Update `validator/sandbox.py` to detect the environment (e.g., presence of `package.json`) and switch the Docker image to `node:slim` or `golang:alpine`.
